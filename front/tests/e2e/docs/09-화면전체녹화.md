# 화면 전체를 찍어야 하는 것들 — 요건과 한계

작성 2026-07-31

지금 촬영은 Playwright 가 **페이지 안쪽만** 담는다. 브라우저 창 자체가 화면에 없으므로 주소창·탭·파일 선택 창·찾기 막대는 어느 것도 나오지 않는다. 그것들이 필요한 시나리오가 있어, 가상 디스플레이에 브라우저를 띄우고 화면을 통째로 찍는 방식을 따로 두기로 했다.

## 1. 왜 나누나

| | 지금 방식 (Playwright) | 화면 전체 (ffmpeg) |
|---|---|---|
| 조작 정밀도 | **높다** — 요소를 식별자로 잡는다 | 낮다 — 좌표·키보드로 몬다 |
| 반복 가능성 | **높다** — 화면이 바뀌어도 식별자로 버틴다 | 낮다 — 배치가 바뀌면 깨진다 |
| 파일 선택 창 | 안 나온다 (열리기 전에 가로챈다) | 나온다 |
| 찾기 막대(Ctrl+F) | 안 나온다 | 나온다 |
| 비트레이트 | **약 1Mbps 고정, 못 바꾼다** | 원하는 대로 |

그래서 **기본은 지금 방식**으로 두고, 화면 전체 촬영은 **꼭 필요한 것만** 짧게 찍는다. 정밀도를 잃는 만큼 시나리오를 늘리면 유지가 안 된다.

대상은 파일이 오가는 것들 — 연결정보 익스포트·임포트, JSON 모델 익스포트·임포트처럼 운영체제 창이 끼는 흐름.

## 2. 두 영상이 달라 보이면 안 된다

이어 붙였을 때 한 편으로 읽혀야 한다. 갈라지기 쉬운 것들:

| 맞춰야 할 것 | 지금 값 |
|---|---|
| **커서 모양** | 페이지 안에 그리는 화살표(`support/cursor.ts`, 22×22 SVG, 그림자 있음, 누를 때 0.82배로 줄고 링이 퍼짐) |
| 창 크기 | 1920×1080 |
| 배율 | `E2E_HQ=1` 일 때 2배 렌더링 |
| 글자 안티에일리어싱 | 회색조(`--disable-lcd-text`) |
| 조작 속도 | `support/humanize.ts` 의 데모 간격 |

**커서가 특히 중요하다.** 화면 전체 촬영에서는 운영체제 커서가 찍히는데 모양이 다르면 그 장면만 이물감이 든다. 운영체제 커서를 숨기고 같은 화살표를 그리거나, 반대로 지금 방식에서도 같은 모양을 쓰도록 맞춘다.

## 3. 화질은 나중에 부분만 올려도 된다

전 구간을 고화질로 다시 찍을 필요는 없다. 글자를 읽어야 하는 구간만 화면 전체 촬영으로 바꿔 비트레이트를 올리면 된다. 지금 방식의 한계(약 1Mbps)는 Playwright 가 정하는 것이라 설정으로 못 바꾼다.

## 4. 편집된 것처럼 보여도 된다

찾아가는 과정을 전부 담을 필요가 없다. **화면이 한 번 움직이는 것만 보이고, 곧바로 필요한 자리로 가서 값을 넣어도 된다** — 중간이 잘린 것처럼 읽히면 그만이다.

그래서 파라미터 훑기는 몇 칸만 굴리고 멈춘다(`E2E_PARAM_SCROLL_NOTCHES`, 기본 6). 끝까지 훑으면 찾는 시간이 그대로 영상에 남는데, 사람이 실제로 하는 일은 한두 번 굴려 보고 아는 자리로 바로 가는 것이다.
